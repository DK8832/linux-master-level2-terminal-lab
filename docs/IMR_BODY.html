리눅스마스터 2급 2차 대비 터미널 실습 기록

리눅스 명령을 읽고 외우는 데서 멈추지 않고, Ubuntu 환경에서 직접 실행한 입력·출력·검증 결과를 남기기 위해 여섯 영역의 터미널 실습을 구성했다. 기존 프로그래밍기능사 웹 학습도구의 Linux 문제와 중복되지 않도록 이번 기록은 실제 명령 실행과 상태 검증에만 집중했다.

1. 목표

파일·권한·텍스트 처리·압축·프로세스·시스템 정보 명령을 한 스크립트에서 안전하게 실행하고, 결과를 8개 체크로 자동 검증한다.

2. 여섯 개 실습

  1. 기본 환경: pwd, id, uname으로 위치·사용자·커널 확인
  2. 파일과 디렉터리: mkdir, cp, mv, find로 복사·이동 결과 검사
  3. 권한: chmod 755, stat, test -x로 실행 권한을 수치와 동작으로 확인
  4. 텍스트 처리: grep, awk, sort -u, wc -l로 ERROR 2행과 고유 사용자 3명 계산
  5. 압축: tar 목록과 SHA-256 해시 기록
  6. 프로세스·시스템: ps, df, free, uptime 출력 확인

3. 안전성과 재현성

모든 파일 작업은 mktemp -d가 만든 임시 폴더 안에서만 수행하고 종료 시 trap으로 정리한다. 사용자 계정 변경, 관리자 권한, 패키지 설치, 네트워크 설정은 사용하지 않았다. GitHub Actions의 ubuntu-latest에서 같은 스크립트를 실행해 누구나 과정을 재현할 수 있다.

4. 검증 결과

  • Linux 커널 문자열 확인
  • 이동 파일 존재와 원본 경로 부재 확인
  • 권한 755 및 실행 가능 상태 확인
  • ERROR 2행, 고유 사용자 3명 확인
  • tar.gz 생성과 SHA-256 출력 확인
  • CHECKS_PASSED=8, LAB_STATUS=PASS 확인
  • Python 로그 검증기 필수 표식 8개 확인

2026년 9월 3일 GitHub Actions run 33694870725를 Ubuntu 24.04.4 LTS에서 실행했다. Bash 문법 검사, 여섯 실습, Python 검증, 로그 아티팩트 업로드 단계가 모두 성공했다.

5. 문제 해결

첫 자동 실행은 겉으로 성공했지만 로그 끝에 CRLF 줄바꿈 오류가 남아 있었다. Bash 파일을 LF로 다시 올리고 워크플로 파이프라인에 pipefail을 강제해 오류가 tee 뒤에 숨지 않게 했다. 수정 후 새 실행에서 오류 없이 통과했다. 또한 ps와 head의 SIGPIPE는 표시용 한 줄에만 예외를 두고 실제 평가 항목은 check 함수가 검사하도록 분리했다. 권한도 ls -l만 보지 않고 stat 숫자값과 test -x를 함께 사용해 교차 확인했다.

6. 배운 점

명령 결과를 외우는 것보다 ‘명령 실행 → 상태 변화 → 다른 명령으로 검증’의 세 단계가 중요하다는 점을 배웠다. 임시 폴더, trap, 엄격 모드를 적용하면 연습 스크립트도 실패를 숨기지 않고 실제 사용자 파일을 건드리지 않게 만들 수 있었다.

7. 한계와 다음 계획

현재 실습은 안전한 일반 사용자 명령에 집중해 계정·서비스·네트워크·패키지 관리처럼 관리자 권한이 필요한 영역은 다루지 않는다. 실행 통과가 시험 합격이나 점수 향상을 의미하지도 않는다. 다음에는 격리된 Linux 가상환경에서 읽기 전용 진단 명령을 중심으로 범위를 확장할 계획이다.

8. AI 활용 및 증빙

실습 구조, Bash 스크립트, Python 검증기, GitHub Actions, 웹 노트, 문서 초안을 만드는 데 Codex를 활용했다. 실제 성공 여부는 Ubuntu 실행 로그와 검증 표식으로 확인하도록 설계했다.
